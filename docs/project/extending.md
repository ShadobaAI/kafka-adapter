# Расширение адаптера

Начните с точки входа, соответствующей задаче. Для изменений в продуктовой подсистеме проверьте [границы модулей](modules.md) и [правила работы с изменениями](contributing.md).

| Задача | Точка расширения |
|---|---|
| Включить ссылочный объект или набор записей в автоматический обмен | Укажите полное имя метаданных в [настройках продюсера](../user/configuration/producers.md#registration-type). Адаптер фильтрует уже подписанные типы. [Подписки на события](modules.md#event-subscriptions) |
| Регистрировать события из прикладного кода | Используйте `кфкИнтеграция.ПоместитьВОчередьИсходящих`. [Программный API](../user/development/api.md#enqueue-outgoing) |
| Изменить формат тела или прикладную обработку | Задайте собственный [обработчик продюсера](../user/development/producer-handler.md) или [обработчик консьюмера](../user/development/consumer-handler.md). |
| Использовать правила преобразования | Настройте [КД 3.1](../user/development/conversion-data.md) и [XDTO](adapter-xdto-requirements.md). |

Если изменение затрагивает способ отбора сообщений, статус очереди или публичный контракт, проверьте затронутые конфигурации и примеры на обеих формах поставки. При изменении правил КД проверьте модуль обмена вместе с XDTO-пакетом и телом сообщения.
