# Обработчик консьюмера

Процедура, которая **обрабатывает тело сообщения**, полученного из Kafka.

В поле **Имя метода десериализации** [консьюмера](../configuration/consumers.md) укажите полное имя экспортной процедуры, например `ОбменKafkaСервер.Десериализация`. Тип **Произвольный обработчик** и имя метода можно задать в [настройках по умолчанию](../configuration/consumers.md#настройки-десериализации-по-умолчанию) на вкладке **Дополнительно** или переопределить в строке табличной части **Топики**. Пустое поле строки наследует соответствующее общее значение. Поле **Имя модуля десериализации** используется для модуля обмена КД 3.1, а не для произвольного обработчика.

## Сигнатура

```bsl
Процедура Десериализация(ТелоСообщения, Свойства, ТекстЖурнала, Отказ) Экспорт
```

## Параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| `ТелоСообщения` | `Строка`, `ДвоичныеДанные` | Тело сообщения из Kafka. Тип зависит от настройки **Двоичные данные** в консьюмере |
| `Свойства` | `Структура` | Дополнительные свойства сообщения — см. [Поля структуры `Свойства`](#поля-структуры-свойства) |
| `ТекстЖурнала` | `Строка` | Текст для журнала входящего сообщения |
| `Отказ` | `Булево`, `Неопределено` | `Ложь` по умолчанию означает успех, `Истина` — отмену, `Неопределено` — запрос отложенного повтора |

## Поля структуры `Свойства` { #поля-структуры-свойства }

| Поле | Тип | Описание |
|------|-----|----------|
| `Консьюмер` | `СправочникСсылка.кфкКонсьюмеры` | Консьюмер, получивший сообщение |
| `Топик` | `Строка` | Имя топика |
| `Ключ` | `Строка` | Ключ сообщения длиной до 50 символов. Если поля `key` нет, ключ формируется из шестнадцатеричной строки SHA-256, вычисленной по XML-представлению тела |
| `Раздел` | `Число` | Номер раздела (partition) |
| `Смещение` | `Число` | Смещение (offset) сообщения в разделе |
| `Заголовки` | `Соответствие Из Строка` | Заголовки сообщения |
| `ДатаЗаписи` | `Дата` | Дата и время из поля `timestamp` сообщения Kafka, приведенные к местному времени |
| `ДатаЗагрузки` | `Дата` | Дата получения сообщения системой |
| `ДатаЗагрузкиМС` | `Число` | Миллисекунды от 01.01.0001 UTC, извлечённые из комбинированной метки загрузки; для пустой метки — `0` |
| `МеткаЗагрузки` | `Число` | Комбинированная метка загрузки сообщения |
| `ДатаОбработки` | `Дата` | Дата и время начала последней попытки обработки, сохранённые в регистре |
| `ВремяОжидания` | `Число` | Задержка перед фоновым повтором в секундах. Целое число от `0` до `300` включительно. В начале каждого вызова равно `30` |

## Минимальный пример

```bsl
Процедура Десериализация(ТелоСообщения, Свойства, ТекстЖурнала, Отказ) Экспорт

    Данные = ОбщегоНазначения.JSONВЗначение(ТелоСообщения, "dateTime", Ложь);

    Элемент = Справочники.Номенклатура.НайтиПоКоду(Данные.code);
    Если Элемент.Пустая() Тогда
        Объект = Справочники.Номенклатура.СоздатьЭлемент();
    Иначе
        Объект = Элемент.ПолучитьОбъект();
    КонецЕсли;

    Объект.Наименование = Данные.name;
    Объект.Код          = Данные.code;

    // ОБЯЗАТЕЛЬНО — иначе запись снова попадёт в очередь исходящих
    кфкИнтеграция.Отключить(Объект);

    Объект.ОбменДанными.Загрузка = Истина;
    Объект.Записать();

КонецПроцедуры
```

## Ключевые правила

### :material-infinity: Идемпотентность обязательна

!!! warning "Повторный вызов"
    Обработчик может быть вызван **повторно** — при перезапуске, ошибке или ручном возврате сообщения в очередь. Проектируйте обработчик так, чтобы повторный вызов с тем же сообщением **не создавал дубликаты** и **не вызывал побочных эффектов**.

Рекомендации:

- для идентификации уже обработанных записей используйте `Свойства.Ключ`, если ключи уникальны с учётом ограничения в 50 символов, либо идентификатор из тела сообщения;
- проверяйте существование объекта по ссылке/ключу перед созданием нового;
- разделяйте обработчики по типам сообщений или топикам — проще гарантировать идемпотентность.

### :material-block-helper: Отключение и `ОбменДанными.Загрузка`

Перед `Записать()` обязательно:

```bsl
кфкИнтеграция.Отключить(Объект);
Объект.ОбменДанными.Загрузка = Истина;
Объект.Записать();
```

- `Отключить()` — блокирует подписку адаптера на событие записи, иначе запись снова попадёт в очередь **исходящих**.
- `ОбменДанными.Загрузка = Истина` — стандартный механизм 1С для подавления бизнес-логики при загрузке данных из внешней системы.

### :material-close-octagon: Отмена обработки

```bsl
Если ТипЗнч(Данные) <> Тип("Структура") Тогда

    ТекстЖурнала = "Корневое значение JSON должно быть объектом";
    Отказ = Истина;
    Возврат;

КонецЕсли;

ЗначениеRef = Неопределено;
Если Не Данные.Свойство("ref", ЗначениеRef) Или Не ЗначениеЗаполнено(ЗначениеRef) Тогда

    ТекстЖурнала = СтрШаблон(
        "Отсутствует поле 'ref'. Топик: %1, смещение: %2",
        Свойства.Топик,
        Свойства.Смещение
    );
    Отказ = Истина;
    Возврат;

КонецЕсли;
```

При успешном завершении обработчика с `Отказ = Истина` сообщение получает статус **«Обработка отменена»**. При ошибке вызова или недопустимом типе `Отказ` адаптер присваивает статус **«Ошибка обработки»**. Журнал сообщения доступен в разделе **Kafka / Входящие сообщения**.

!!! info "Ручная обработка"
    Команда **Обработать сообщение** в карточке или списке сразу запускает попытку для одной записи. Администратор может повторить обработку после ошибки или отмены, а также обработать сообщение в статусе **«Новое»** до истечения задержки. Команда **Вернуть в очередь** переводит запись со статусом **«Ошибка обработки»** в **«Новое»** для фоновой обработки. [Условия ручного запуска](../operations/statuses.md#ручные-операции-в-рс)

### Отложенный повтор

Чтобы отложить обработку, установите `Отказ = Неопределено` и завершите процедуру. При необходимости задайте задержку в секундах через `Свойства.ВремяОжидания`.

```bsl
Свойства.ВремяОжидания = 60;
Отказ = Неопределено;
Возврат;
```

При допустимом запросе адаптер сохраняет задержку в записи со статусом **«Новое»**. Поток отсчитывает задержку от начала последней попытки по времени сеанса (`ДатаОбработки + ВремяОжидания`). Если диспетчер выбрал запись раньше, поток возвращает её в конец очереди. Дата, длительность и счётчик попыток сохраняются. При нулевой задержке следующая попытка возможна уже на следующем проходе.

Сохранённая задержка видна в списке входящих сообщений и в поле **«Задержка, с»** на вкладке **«Свойства»** карточки.

Запрос задержки свыше 300 секунд переводит сообщение в статус **«Ошибка обработки»**. Например, при запросе на `301` секунду уже на первой попытке в журнале появится «Время ожидания превышает 5 минут». При допустимой задержке обработчик может запросить повтор на попытках с 1-й по 100-ю. На 101-й и последующих попытках он может завершиться успехом или отменой. Если обработчик снова запросит повтор с допустимой задержкой, запись получит статус **«Ошибка обработки»** с текстом «Исчерпан лимит повторов».

#### Запись заказа после загрузки контрагента

В примере консьюмер получает текстовый JSON при выключенной настройке **Двоичные данные**. У документа `ЗаказКлиента` есть реквизит `Контрагент` типа `СправочникСсылка.Контрагенты`. Сообщение содержит `ref` (UUID заказа), `customerRef` (UUID контрагента) и `dateTime` (дату заказа в формате ISO 8601). Элемент справочника загружается из другого топика под тем же UUID, который передан в `customerRef`.

```bsl
Процедура ДесериализацияЗаказа(ТелоСообщения, Свойства, ТекстЖурнала, Отказ) Экспорт

    Данные = ОбщегоНазначения.JSONВЗначение(ТелоСообщения, "dateTime", Ложь);
    СсылкаКонтрагента = Справочники.Контрагенты.ПолучитьСсылку(
        Новый УникальныйИдентификатор(Данные.customerRef));

    Если Не ОбщегоНазначения.СсылкаСуществует(СсылкаКонтрагента) Тогда
        Свойства.ВремяОжидания = 60;
        Отказ = Неопределено;
        Возврат;
    КонецЕсли;

    СсылкаЗаказа = Документы.ЗаказКлиента.ПолучитьСсылку(
        Новый УникальныйИдентификатор(Данные.ref));
    Если ОбщегоНазначения.СсылкаСуществует(СсылкаЗаказа) Тогда
        Заказ = СсылкаЗаказа.ПолучитьОбъект();
    Иначе
        Заказ = Документы.ЗаказКлиента.СоздатьДокумент();
        Заказ.УстановитьСсылкуНового(СсылкаЗаказа);
    КонецЕсли;

    Заказ.Дата = Данные.dateTime;
    Заказ.Контрагент = СсылкаКонтрагента;
    кфкИнтеграция.Отключить(Заказ);
    Заказ.ОбменДанными.Загрузка = Истина;
    Заказ.Записать();

КонецПроцедуры
```

При первом вызове `СсылкаСуществует` возвращает `Ложь`, и обработчик завершает работу до записи заказа, запросив повтор через 60 секунд. Если к следующему вызову контрагент уже загружен, проверка проходит и обработчик записывает заказ со ссылкой на него.

!!! warning "Важно"
    Адаптер допускает до 100 отложенных повторов. Если на 101-й попытке обработки контрагент всё ещё отсутствует, новый запрос повтора переводит сообщение в статус **«Ошибка обработки»**. В журнале сообщения появляется «Исчерпан лимит повторов».
