# Обработчик консьюмера

Произвольный обработчик получает тело сообщения из входящей очереди и выполняет прикладную операцию в 1С. Адаптер регистрирует результат в записи очереди.

## Подключение { #configuration }

В форме [консьюмера](../configuration/consumers.md) выберите **Произвольный обработчик** и в поле **Имя метода десериализации** укажите полное имя экспортной процедуры, например `ОбменKafkaСервер.Десериализация`. Настройку можно задать для конкретного топика или [по умолчанию](../configuration/consumers.md#deserialization-defaults). Поле **Имя модуля десериализации** относится к [Конвертации данных 3.1](conversion-data.md).

## Сигнатура { #signature }

```bsl
Процедура Десериализация(ТелоСообщения, Свойства, ТекстЖурнала, Отказ) Экспорт
```

| Параметр | Назначение |
|---|---|
| `ТелоСообщения` | `Строка` или `ДвоичныеДанные` в зависимости от флага **Двоичные данные** у консьюмера. |
| `Свойства` | [Структура с полями сообщения и задержкой повтора](#message-properties). |
| `ТекстЖурнала` | Строка для журнала записи. Адаптер передаёт пустую строку и добавляет возвращённый текст в журнал. |
| `Отказ` | `Ложь` при входе в процедуру. Присвойте `Истина` для отмены или `Неопределено` для отложенного повтора. |

### Поля структуры «Свойства» { #message-properties }

| Поле | Тип и значение |
|---|---|
| `Консьюмер` | `СправочникСсылка.кфкКонсьюмеры`. Консьюмер, получивший сообщение. |
| `Топик`, `Ключ` | `Строка`. Имя топика и сохранённый ключ сообщения длиной до 50 символов. При отсутствии ключа адаптер формирует его из SHA-256 XML-представления тела. |
| `Раздел`, `Смещение` | `Число`. Раздел Kafka и смещение внутри раздела. |
| `Заголовки` | Заголовки сообщения, если они были переданы. |
| `ДатаЗаписи` | `Дата`. Метка времени сообщения Kafka, приведённая к местному времени. |
| `ДатаЗагрузки` | `Дата`. Время получения сообщения адаптером. |
| `ДатаЗагрузкиМС` | `Число`. Миллисекунды UTC с 01.01.0001, извлечённые из метки загрузки. Для пустой метки передаётся `0`. |
| `МеткаЗагрузки` | `Число`. Комбинированная метка загрузки. |
| `ДатаОбработки` | `Дата`. Начало предыдущей попытки, сохранённое в записи до текущего вызова. |
| `ВремяОжидания` | `Число`. Задержка в секундах, если обработчик запросит повтор. При каждом вызове адаптер задаёт `30`. |

## Результат обработки { #result }

| Результат вызова | Статус записи |
|---|---|
| `Отказ = Ложь` | **Обработано**. |
| `Отказ = Истина` | **Обработка отменена**. Причину можно передать через `ТекстЖурнала`. [Пример отмены](../examples/incoming-cancel.md) |
| `Отказ = Неопределено` | **Новое**, если запрос укладывается в лимиты [отложенного повтора](#deferred-retry). |
| Исключение, недопустимое значение `Отказ` или превышение лимита повтора | **Ошибка обработки**. Подробности ищите в журнале записи раздела **Kafka → Входящие сообщения**. |

## Отложенный повтор { #deferred-retry }

Установите `Отказ = Неопределено` и завершите процедуру. Чтобы изменить задержку, присвойте `Свойства.ВремяОжидания` целое число секунд от `0` до `300`. Без присваивания используется `30`. Нулевая задержка разрешает обработку при следующем фоновом отборе.

Адаптер сохраняет задержку в записи и оставляет статус **Новое**. Начало текущей попытки задаёт точку отсчёта даже при длительном вызове обработчика. Следующий вызов возможен, когда фоновый поток выберет запись после этого срока. Если поток выбрал запись раньше, он обновляет `МеткаИзменения` и переносит её в конец очереди. Обработчик в этот проход не вызывается, счётчик и время начала попытки не меняются.

| Условие при запросе повтора | Результат |
|---|---|
| Задержка больше `300` секунд | **Ошибка обработки**. В журнале «Время ожидания превышает 5 минут.» |
| Задержка в пределах лимита и счётчик попыток уже больше `100` | **Ошибка обработки**. В журнале «Исчерпан лимит повторов.» |

На 100-й попытке ещё можно запросить повтор. На 101-й обработчик может успешно завершиться или отменить обработку. Лимит применяется при очередном запросе повтора.

Сохранённое значение видно в карточке входящего сообщения на вкладке **Свойства** в поле **Задержка, с**. Команда **Обработать сообщение** позволяет вручную запустить попытку без ожидания задержки. [Условия ручного запуска](../operations/statuses.md#manual-actions)

## Запись данных в 1С { #writing-data }

Учитывайте повторный вызов. Например, ищите объект по UUID из сообщения и обновляйте его по тому же ключу. Проверки зависимостей и условия отмены выполняйте до записи данных.

Чтобы изменение из Kafka не зарегистрировалось как новое исходящее событие, вызовите `кфкИнтеграция.Отключить(Объект)` перед записью объекта или набора записей, участвующего в исходящем обмене. Устанавливайте `ОбменДанными.Загрузка = Истина`, если прикладные обработчики вашей конфигурации должны выполнять запись в режиме загрузки.
