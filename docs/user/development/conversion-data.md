# Конвертация данных 3.1

Альтернативный способ преобразования данных — через механизм **[1С:Конвертация данных 3.1](http://its.1c.ru/db/metod8dev#content:5846:hdoc)**.

## Когда выбирать КД 3.1

| Произвольный обработчик | КД 3.1 |
|---|---|
| Быстрый старт, код «здесь и сейчас» | Медленный старт — нужен XDTO-пакет и модуль обмена |
| Логика преобразования в коде прикладного решения | Правила — в визуальной среде КД |
| Легко переделывать | Стабильный контракт, визуальная документация |
| Подходит для простых случаев | Подходит для сложных контрактов и межсистемной интеграции |

## Что нужно подготовить

1. **XDTO-пакет** — описывает XML-структуру передаваемых данных. Создаётся в EDT или Конфигураторе.
2. **Модуль обмена** — генерируется в **КД 3.1** и реализует правила преобразования данных в XDTO и обратно.

## Как настроить

### На стороне продюсера

В форме [продюсера](../configuration/producers.md) задайте общие параметры на вкладке **Дополнительно**, в группе **Настройки сериализации по умолчанию**, либо укажите их в строке табличной части **Объекты метаданных**:

| Поле | Значение |
|------|----------|
| **Тип сериализации** | `Конвертация данных` |
| **Имя модуля сериализации** | Обязательное имя общего модуля менеджера обмена, сгенерированного в КД 3.1 |
| **Имя ПОД сериализации** | Имя правил обработки данных из этого модуля обмена |
| **Формат сериализации** | URI пространства имён XDTO-пакета или [маска для выбора версии](#подбор-формата-xdto) |

Имя модуля сериализации должно быть задано в строке или в настройках по умолчанию. Тип, модуль и формат наследуются независимо для каждого пустого поля строки; **имя ПОД указывается только в строке**. Поле **Имя метода сериализации** для КД 3.1 не используется: адаптер вызывает правила из указанного модуля обмена.

### На стороне консьюмера

В форме [консьюмера](../configuration/consumers.md) задайте общие параметры на вкладке **Дополнительно**, в группе **Настройки десериализации по умолчанию**, либо укажите их в строке табличной части **Топики**:

| Поле | Значение |
|------|----------|
| **Тип десериализации** | `Конвертация данных` |
| **Имя модуля десериализации** | Обязательное имя общего модуля менеджера обмена КД 3.1 |
| **Имя ПОД десериализации** | Имя правил обработки данных из этого модуля обмена |
| **Формат десериализации** | URI пространства имён XDTO-пакета или [маска для выбора версии](#подбор-формата-xdto) |

Имя модуля десериализации должно быть задано в строке или в настройках по умолчанию. Тип, модуль и формат наследуются независимо для каждого пустого поля строки; **имя ПОД указывается только в строке**. Поле **Имя метода десериализации** для КД 3.1 не используется.

### Подбор модуля обмена и ПОД

В списке выбора имени модуля предлагаются серверные менеджеры обмена с версией формата `2` или `2.КФК`. Не предлагаются модули, доступные в управляемом клиенте, а также модули с повторным использованием возвращаемых значений.

Список ПОД берётся из выбранного модуля обмена с учётом направления: отправка у продюсера, получение у консьюмера. У консьюмера для подбора ПОД также требуется формат десериализации. При пустых полях строки используются общие настройки модуля и формата.

## Подбор формата XDTO { #подбор-формата-xdto }

Поля **Формат сериализации** и **Формат десериализации** принимают точный URI пространства имён или маску. Это работает как в строке, так и в настройках по умолчанию. Список выбора содержит пространства имён доступных адаптеру XDTO-пакетов; при вводе текста можно подобрать URI по фрагменту имени.

Маска применяется при подготовке правил обмена: адаптер автоматически выбирает конкретный URI пакета. Если в строке формат пуст, сначала берётся формат по умолчанию, затем выполняется подбор.

| Запись | Значение |
|--------|----------|
| `http://v8.fsk.ru/kfk/test/2.1` | Точный URI, используется без подбора |
| `http://v8.fsk.ru/kfk/test/*` | Любая последовательность символов после `test/`, кроме `/` |
| `http://v8.fsk.ru/kfk/test/2.*` | Версии в последнем сегменте, начинающиеся с `2.` |
| `http://v8.fsk.ru/kfk/**/test/*` | `**/` допускает ноль или несколько промежуточных сегментов пути |
| `http://v8.fsk.ru/kfk/**` | `**` допускает любые символы, включая `/`; широкую маску нужно ограничить одним форматом |

Маска сопоставляется со всем URI. Обычный префикс без `*` считается точным URI. Несколько звёздочек подряд трактуются как `**`.

Правила выбора:

1. **Нет совпадений** — ошибка «Не найден пакет XDTO по шаблону…».
2. **Одно совпадение** — используется найденный URI; наличие версии в нём не требуется.
3. **Несколько совпадений** — у всех URI должна совпадать основа до версии, а последний сегмент должен содержать от **1 до 4 числовых частей**, разделённых точками. Адаптер выбирает **максимальную числовую версию**. Недостающие части считаются нулевыми; при равных версиях используется первое найденное совпадение.

Например, для пакетов `http://v8.fsk.ru/kfk/test/1.0`, `http://v8.fsk.ru/kfk/test/2.0` и `http://v8.fsk.ru/kfk/test/2.1` маска `http://v8.fsk.ru/kfk/test/*` выберет **`2.1`**. Версия `1.2.10` считается новее `1.2.9`.

Если маска выбирает несколько URI с разными основами либо с неподходящей версией, подбор завершается ошибкой. Уточните маску или укажите точный URI. URI без `*` передаётся дальше без проверки наличия пакета на этапе подбора.

## Пакетная модель для регистров по регистратору

Для регистров накопления, бухгалтерии, расчёта и РС в режиме **ПодчинениеРегистратору**:

- Адаптер **сам** выполняет запрос всех записей по регистратору.
- Правила КД 3.1 применяются **к каждой записи**.
- Результат — **одно сообщение**, тело которого содержит **массив** объектов.

!!! info "Почему пакет"
    Чтение через «набор с отбором» не используется из соображений производительности.

## Варианты XDTO-пакета

### Вариант 1. Стандартный XDTO (EnterpriseData)

Используется формат **EnterpriseData** — стандарт 1С для межсистемного обмена данными. Перед настройкой проверьте, что XDTO-пакет выбранной версии EnterpriseData и его зависимости доступны в глобальной фабрике XDTO вашей конфигурации, а правила модуля обмена соответствуют этой версии. Само наличие платформы 1С не гарантирует наличие нужного пакета.

Подробно формат описан в официальной документации: [Формат EnterpriseData](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/format-enterprisedata/).

**Подходит когда:** принимающая сторона работает с типовыми конфигурациями 1С и понимает формат EnterpriseData.

### Вариант 2. Произвольный XDTO

XDTO-пакет под **конкретный контракт** данных. Создаётся двумя способами:

**а) Вручную в EDT или Конфигураторе** — стандартными средствами платформы.

**б) Из AsyncAPI-спецификации** — с помощью скрипта [`asyncapi2xsd.py`](https://github.com/ShadobaAI/kafka-tools/blob/main/xdto/generator/asyncapi2xsd.py) (репозиторий [Набор скриптов](https://github.com/ShadobaAI/kafka-tools)). Подробнее — [Генерация XSD из YAML](../../project/xsd-generation.md).
