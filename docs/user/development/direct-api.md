# Прямой API

Методы общего модуля `кфкИнтеграция` обращаются к Kafka в текущем вызове без регистров-очередей адаптера. Прикладной код проверяет результат и решает, повторять ли операцию. Возвращаемые ошибки сопровождаются `ТекстОшибки`. Исключения 1С обрабатывайте у вызывающего кода.

## Отправить сообщение { #send-message }

```bsl
Отправить(Продюсер, ИмяТопика, Сообщение, Партиция = -1, Сессии = Неопределено)
```

| Параметр | Значение |
|---|---|
| `Продюсер` | `СправочникСсылка.кфкПродюсеры`. Из настройки берутся параметры подключения и клиента. |
| `ИмяТопика` | Строка с именем топика Kafka. |
| `Сообщение` | Структура из [ПараметрыСообщения](api.md#message-parameters). |
| `Партиция` | Номер раздела. При `-1` раздел выбирает Kafka-клиент. |
| `Сессии` | `Соответствие` для [переиспользования подключения](#sessions) или `Неопределено` для одного вызова. |

Результат содержит `Успешно` и `ТекстОшибки`. При отправке адаптер использует результат, возвращённый внешней компонентой. Параметры подтверждения записи задаются в настройках Kafka-клиента, например через `acks`.

## Прочитать сообщение { #read-messages }

```bsl
Прочитать(Консьюмер, АвтоФиксацияСмещения, Сессии = Неопределено)
```

| Параметр | Значение |
|---|---|
| `Консьюмер` | `СправочникСсылка.кфкКонсьюмеры`. Используются параметры консьюмера, включая топики и группу. |
| `АвтоФиксацияСмещения` | `Булево`. Задаёт режим автофиксации при создании сессии. |
| `Сессии` | `Соответствие` для повторных вызовов или `Неопределено` для одного вызова. |

Результат содержит `Успешно`, `ТекстОшибки` и `Сообщение`. Когда компонента не вернула сообщение, поле `Сообщение` равно `Неопределено`. У полученного сообщения доступны `Тело`, `Ключ`, `Заголовки`, `Топик`, `ВременнаяМетка`, `Раздел` и `Смещение`. Временная метка Kafka передаётся в миллисекундах Unix. Заголовки приходят как разобранное значение JSON компоненты, при отсутствии заголовков — `Неопределено`.

При одиночном вызове без `Сессии` адаптер пытается зафиксировать `Смещение + 1` до возврата сообщения независимо от `АвтоФиксацияСмещения`. При ошибке фиксации `Успешно` равно `Ложь`, а прочитанные данные остаются в `Сообщение`.

При передаче `Сессии` метод чтения полагается на режим фиксации созданного коннектора. Для сохранения сообщения в 1С до запуска обработчика используйте [обмен через входящую очередь](../../overview/data-flow.md#incoming).

## Переиспользование сессий { #sessions }

Передайте пустое `Соответствие` в первый вызов. Адаптер сохраняет сессию по ссылке на продюсер или консьюмер. Передавайте эту же коллекцию при следующих вызовах одного вида. По завершении, включая ветку исключения, вызовите соответствующий метод закрытия.

- `ЗакрытьСессииПродюсера(Сессии)`.
- `ЗакрытьСессииКонсьюмера(Сессии)`.

Используйте новую коллекцию для последующих операций после закрытия. [Примеры отправки и чтения](../examples/direct-api.md)
