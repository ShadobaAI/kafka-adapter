# Обработчик продюсера

Произвольный обработчик формирует тело, ключ и заголовки исходящего сообщения. Адаптер вызывает его на этапе сериализации записи очереди.

## Подключение { #configuration }

В форме [продюсера](../configuration/producers.md) задайте тип **Произвольный обработчик** и полное имя экспортной функции, например `ОбменKafkaСервер.Сериализация`. Имя можно указать по умолчанию или в конкретной строке **Объекты метаданных**. [Наследование настроек](../configuration/producers.md#serialization-defaults)

## Сигнатура { #signature }

```bsl
Функция Сериализация(Объект, Свойства, ТекстЖурнала, Отказ) Экспорт
```

| Параметр | Назначение |
|---|---|
| `Объект` | [Данные, полученные при регистрации](#handler-input). |
| `Свойства` | [Дополнительные поля регистрации](#message-properties). |
| `ТекстЖурнала` | Строка для поля **Текст журнала** исходящего сообщения. |
| `Отказ` | `Булево`. Значение `Истина` отменяет сериализацию, запись получает статус **Обработка отменена**. |

### Входные данные обработчика { #handler-input }

| Как зарегистрировано | Что приходит в `Объект` |
|---|---|
| Подпиской на запись или удаление ссылочного объекта | Объект 1С, например `СправочникОбъект` или `ДокументОбъект`. |
| Передачей ссылки через `ПоместитьВОчередьИсходящих` | Переданная ссылка. |
| Записью независимого регистра сведений | Структура с полями записи и дополнительными свойствами. При регистрации пустого набора проверьте признак удаления и доступные поля отбора. |
| Записью регистра, подчинённого регистратору | Структура с полем `Регистратор` и дополнительными свойствами. Записи по регистратору запрашивает сам произвольный обработчик. |
| Передачей произвольных данных | Переданная структура или соответствие. Готовое сообщение из `ПараметрыСообщения` идёт сразу на выгрузку. |

### Поля структуры «Свойства» { #message-properties }

| Поле | Значение |
|---|---|
| `Продюсер` | `СправочникСсылка.кфкПродюсеры`. |
| `ТипОбъект` | Ключ регистрации из настроек продюсера. |
| `ТипИсходныхДанных` | Строковое описание типа исходных данных. |
| `СобытиеРегистрации` | `ПеречислениеСсылка.кфкСобытияРегистрации`. Проверяйте [методами API](api.md#is-write-registration). |
| `КлючРегистрации` | Логический ключ записи очереди. |
| `ДатаРегистрации` | Дата и время регистрации. |
| `ДатаРегистрацииМС` | Миллисекунды UTC с 01.01.0001 из метки регистрации. Для пустой метки — `0`. |
| `СеансРегистрации` | Номер сеанса из метки регистрации. Для пустой или временной граничной метки — `0`. |
| `ПоследняяОбработка` | Дата последней обработки сообщения. |
| `ЭтоУдаление` | `Булево`. Признак регистрации удаления. |
| `СсылкаНаОбъект` | Ссылка на объект регистрации или `Неопределено`. |

## Результат { #result }

Для выгрузки верните структуру из [ПараметрыСообщения](api.md#message-parameters). Структура и массив структур в поле `Данные` преобразуются в JSON. Строка или двоичное тело передаются как есть.

Чтобы отменить сериализацию, установите `Отказ = Истина`, запишите причину в `ТекстЖурнала` и верните `Неопределено`. При возврате `Неопределено` с `Отказ = Ложь` запись получает статус **Ошибка обработки**.

## Ключ сообщения { #message-key }

При пустом поле `Ключ` используется `КлючОбъекта` исходящей записи. `Свойства.КлючРегистрации` служит для отбора и дедупликации внутри адаптера и учитывает также тип и продюсера.

Раздел для Kafka-ключа определяет настройка партиционирования клиента. Kafka хранит сообщения в порядке поступления внутри раздела. Порядок отправки из параллельных потоков адаптера зависит от выполнения этих потоков.
