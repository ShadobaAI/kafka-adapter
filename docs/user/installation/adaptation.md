# Настройка в EDT / Конфигураторе

Действия, которые необходимо выполнить на уровне метаданных и модулей — **один раз**, при первом подключении адаптера к целевой конфигурации.

## Определяемый тип `кфкПользователь`

В адаптере определён тип `кфкПользователь` для хранения ссылок на пользователей. По умолчанию он указывает на `СправочникСсылка.Пользователи` — служебный справочник из состава адаптера, предназначенный **только для разработки**.

!!! warning "Обязательно заменить"
    При внедрении в прикладную конфигурацию **замените** тип на `СправочникСсылка.Пользователи` **целевой** конфигурации (обычно он есть в БСП — `Справочник.Пользователи`).

### Как заменить

=== "EDT"

    1. Откройте дерево → **Общие → Определяемые типы → `кфкПользователь`**.
    2. Двойным щелчком откройте тип.
    3. В окне «Тип данных» укажите справочник пользователей целевой конфигурации (в типовых конфигурациях — обычно `СправочникСсылка.Пользователи`).
    4. Сохраните проект.
    5. Обновите конфигурацию базы данных.

=== "Конфигуратор"

    1. Откройте дерево конфигурации → **Общие → Определяемые типы → `кфкПользователь`**.
    2. Двойным щелчком откройте тип.
    3. В окне «Тип данных» укажите справочник пользователей целевой конфигурации (в типовых конфигурациях — обычно `СправочникСсылка.Пользователи`).
    4. Обновите конфигурацию базы данных.

## Оптимизация подписок на события

По умолчанию [подписки адаптера](../../project/modules.md#подписки-на-события) охватывают **все** ссылочные объекты и все наборы записей регистров — фильтрация по настройкам продюсера выполняется в обработчике.

!!! tip "Рекомендация"
    Чтобы избежать избыточных срабатываний подписок и повысить производительность, **сузьте состав источников** подписок под реальные потребности обмена:

    - **Удалите/не переносите** подписки для типов объектов, которые не будут участвовать в обмене. Например, если регистры расчёта не выгружаются — удалите подписку `кфкЗарегистрироватьИзмененияНабораРасчетаПриЗаписи`.
    - В подписке `кфкЗарегистрироватьИзмененияПриЗаписи` и `кфкЗарегистрироватьИзмененияПередУдалением` замените **«Любая ссылка»** на перечень конкретных ссылочных типов, которые реально участвуют в обмене.
    - В подписке `кфкЗарегистрироватьИзмененияНабораПриЗаписи` оставьте только нужные регистры (сведений/накопления/бухгалтерии) и уберите неиспользуемые — например, если выгружаются только регистры сведений, исключите регистры накопления и бухгалтерии.

    После сужения источников функциональность адаптера не меняется — объекты всё равно должны быть указаны в настройках [продюсера](../configuration/producers.md).

## Подключение к подсистемам БСП

Подключите методы общего модуля `кфкИнтеграция` к соответствующим обработчикам БСП целевой конфигурации. Передавайте параметры обработчиков без изменений.

### Регламентные задания

!!! warning "Обязательное подключение регламентного задания"
    Обязательно подключите `кфкИнтеграция.ПриОпределенииНастроекРегламентныхЗаданий` при внедрении адаптера. Без этого вызова адаптер не передает БСП признак работы задания с внешними ресурсами и его зависимость от функциональной опции. Нельзя рассчитывать на штатное отключение задания БСП при блокировке внешних ресурсов только на основании проверки в начале выполнения задания.

В процедуре `РегламентныеЗаданияПереопределяемый.ПриОпределенииНастроекРегламентныхЗаданий` добавьте вызов:

```bsl
кфкИнтеграция.ПриОпределенииНастроекРегламентныхЗаданий(Настройки);
```

Метод связывает задание `кфкЗапускИнтеграции` с функциональной опцией `кфкИспользоватьИнтеграцию` и устанавливает `РаботаетСВнешнимиРесурсами = Истина`. Это подключает задание к штатным проверкам доступности и блокировки внешних ресурсов БСП. Условия запуска описаны в разделе [Регламентное задание](../configuration/jobs.md#регламентное-задание).

### Подключаемые команды

В процедуре `ПодключаемыеКомандыПереопределяемый.ПриОпределенииКомандПодключенныхКОбъекту` добавьте вызов:

```bsl
кфкИнтеграция.ПриОпределенииКомандПодключенныхКОбъекту(
    НастройкиФормы, Источники, ПодключенныеОтчетыИОбработки, Команды);
```

Метод добавляет команду **«История выгрузки (Kafka)»** в меню **«Еще»** форм объектов, участвующих в интеграции. Видимость команды зависит от функциональной опции `кфкИспользоватьИнтеграцию`.

### При подключении как расширение

Заимствуйте соответствующие общие модули БСП в расширение, подключающее адаптер. Для каждой процедуры создайте обработчик с аннотацией `&После`, указав имя процедуры БСП, и разместите в нем соответствующий вызов `кфкИнтеграция`.

Примеры находятся в проекте [examples](https://github.com/ShadobaAI/kafka-adapter-examples):

- `РегламентныеЗаданияПереопределяемый.кфк_т_ПриОпределенииНастроекРегламентныхЗаданий`;
- `ПодключаемыеКомандыПереопределяемый.кфк_т_ПриОпределенииКомандПодключенныхКОбъекту`.
