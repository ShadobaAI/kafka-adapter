# Обновление версий

Как обновить уже внедрённый адаптер на новую версию. Новые версии публикуются в [GitHub Releases](https://github.com/ShadobaAI/kafka-adapter/releases); состав файлов релиза — [Форматы поставки](../../project/delivery-formats.md).

## Перед обновлением — в любом варианте

1. **Прочитайте описание релиза** — там перечислены изменения и возможные особенности перехода.
2. **Остановите обмен**: на вкладке **Kafka / Администрирование / Фоновые задания** нажмите **Заблокировать** и дождитесь завершения активных потоков; отключите регламентное задание.
3. **Сделайте резервную копию** информационной базы.
4. Выберите момент, когда очереди максимально разобраны — так меньше сообщений «переживёт» обновление в промежуточных статусах.

Если обновление переводит регистры обмена на комбинированные метки, **до загрузки новой конфигурации** выполните предварительную проверку из раздела [«Переход на комбинированные метки»](#переход-на-комбинированные-метки). После обновления схемы вызовите метод миграции, сохраняя блокировку обмена.

## Вариант «расширение конфигурации»

=== "Конфигуратор"

    1. Получите новый файл `Adapter Kafka v*.cfe` из релиза.
    2. Откройте **Конфигурация → Расширения конфигурации**.
    3. Выберите расширение адаптера и загрузите новую версию: **Конфигурация → Загрузить конфигурацию из файла** (или удалите старое расширение и добавьте новое — настройки хранятся в данных базы и при этом не теряются).
    4. Обновите конфигурацию базы данных.
    5. Повторите шаги из [Адаптации подсистемы](adaptation.md), если они выполнялись (замена определяемого типа `кфкПользователь` в расширении).

=== "EDT — через библиотеку"

    Если проект расширения создан на **поддержке библиотеки** (`.xlib`), обновление сводится к обновлению библиотеки до новой версии и повторному развёртыванию проекта — ручное слияние не требуется. Подробнее: [1С:EDT — Работа с библиотеками](https://its.1c.ru/db/edtdoc#content:10626:hdoc).

## Вариант «основная конфигурация»

=== "Конфигуратор"

    1. Получите новый файл `Adapter Kafka v*.cf` из релиза.
    2. Выполните **Конфигурация → Сравнить, объединить с конфигурацией из файла**, отобрав объекты с префиксом `кфк`.
    3. Если объекты адаптера дорабатывались в вашей конфигурации — проверьте слияние по каждому изменённому объекту.
    4. Обновите конфигурацию базы данных.

=== "EDT — через библиотеку"

    Если конфигурация ведётся в EDT на поддержке библиотеки (`.clib`), обновите библиотеку до новой версии и разверните проект — изменения адаптера придут без ручного слияния.

## После обновления

Если новая версия переводит регистры обмена на комбинированные метки, сначала выполните описанную ниже миграцию. Для остальных версий переходите к запуску обмена.

1. После нужной миграции включите регламентное задание и снимите блокировку (**Разблокировать**).
2. Убедитесь, что подсистема включена: **Kafka / Администрирование**.
3. Проверьте, что очереди разбираются: статусы новых сообщений доходят до «Выгружено» / «Обработано» — см. [Мониторинг очередей](../operations/monitoring.md).
4. Просмотрите журнал регистрации на предмет ошибок фоновых заданий.

## Переход на комбинированные метки

При переходе на комбинированные метки технические поля регистров обмена получают неотрицательный тип `Число(30,0)`. Первичные метки сообщений, метки изменения, копии в очереди потоков и позиции операций используют составное число: миллисекунды UTC от 01.01.2026, номер сеанса и порядковый номер.

!!! warning "Ограничения миграции"
    `кфкИнтеграция.ОбновитьКомбинированныеМетки()` обрабатывает регистры сообщений, хэш-сумм и позиций, но не переносит очередь потоков. Нулевые позиции сохраняются; нулевые метки сообщений и хэш-сумм из отбора не исключены и преобразуются в отрицательные значения. Диапазон исторических дат автоматически не проверяется. Перед применением проверьте миграцию на копии ИБ; при наличии нулевых меток сообщений или хэш-сумм требуется исправить их обработку.

1. До обновления разберите старые строки очереди потоков: после изменения первичных меток сообщений сохранённые копии в очереди перестанут им соответствовать. Затем заблокируйте интеграцию, остановите регламентные и интерактивные обработчики, дождитесь завершения потоков и транзакций. Сделайте резервную копию ИБ.
2. **До изменения схемы** проверьте фактические значения `ДатаЗагрузкиМС`. Если сохранены дробные ключи, остановите обновление: перевод в `Число(30,0)` потеряет дробную часть. Проверьте также исторические даты: значения до начала 2026 года не помещаются в неотрицательную шкалу метки. На копии ИБ проверьте сохранность строк и значений после переименования и расширения полей.
3. Обновите конфигурацию и конфигурацию базы данных. Не запускайте обработчики обмена.
4. После проверки миграции на копии ИБ вызовите на сервере `кфкИнтеграция.ОбновитьКомбинированныеМетки()`. Процедура выполняется в привилегированном режиме. Исключите параллельную миграцию и другие записи. Заранее установленная блокировка сохраняется; если обработчик установил её сам, после успеха он её снимет.
5. Сверьте количество записей, сохранность временной составляющей, отсутствие старых ненулевых меток и уникальность меток изменения отдельно для каждого направления. Автоматического контроля числа строк и отчёта о преобразованиях нет. При ошибке оставьте обмен заблокированным и проверьте уже записанные порции перед повторным вызовом.
6. После успешной проверки возобновите обмен по разделу «После обновления».

Миграция использует порции до 10000 строк. В каждом регистре счётчик начинается с `1`, продолжается между порциями и после `99999999` переходит к `1`. Компонент сеанса равен `0`; обоим полям сообщения назначается один порядковый номер. Позиции тоже получают ненулевой порядковый номер. При отборе сообщений проверяется только метка изменения, поэтому смешанный старый и новый формат двух полей не поддерживается.

Первичная метка входит в `id` внешнего лога. После миграции он меняется; повторная выгрузка исторической миллисекунды может создать документы со старым и новым `id`. Учтите это во внешнем хранилище. Уже полные дубли меток миграция не исправляет: при их наличии оставьте обмен заблокированным до исправления данных.

!!! info "Внешняя компонента обновляется вместе с подсистемой"
    Simple Kafka Connector 1C входит в состав поставки — отдельно обновлять его не нужно. Требуемая версия компоненты — **1.9.2+**.

!!! warning "Новые объекты и права"
    Если в новой версии появились объекты метаданных, роли `кфкБазовыеПрава` / `кфкПолныеПрава` обновятся вместе с подсистемой. Но если вы раздавали права на объекты адаптера собственными ролями — дополните их вручную. См. [Роли и права](roles.md).
