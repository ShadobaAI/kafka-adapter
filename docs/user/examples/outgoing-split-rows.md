# Разделение табличных данных на отдельные сообщения

Обработчик регистрации справочника читает табличную часть `Товары` и ставит в очередь одно готовое сообщение на строку. Состав полей в примере подходит для передачи текущего списка. Если потребитель должен узнавать об удалениях, добавьте в контракт явные события для удалённых строк.

## Настройка продюсера { #producer-setup }

| Тип объект | Имя топика | Обработка |
|---|---|---|
| `Справочник.Комплекты` | Топик нужен, если публикуете и шапку | Произвольный обработчик `ОбменKafkaСервер.СериализоватьСтрокиКомплекта` |
| `catalog.rows` | `catalog.rows` | Готовые сообщения, зарегистрированные из обработчика |

Первая строка реагирует на запись справочника. Вторая принимает данные от вызова API по ключу `catalog.rows`.

## Обработчик справочника { #handler }

```bsl
Функция СериализоватьСтрокиКомплекта(Объект, Свойства, ТекстЖурнала, Отказ) Экспорт

    Отказ = Истина;
    Если Свойства.ЭтоУдаление Тогда
        Возврат Неопределено;
    КонецЕсли;

    ИдентификаторКомплекта = Строка(Объект.Ссылка.УникальныйИдентификатор());
    Сообщения = Новый Массив;

    Для Каждого СтрокаТоваров Из Объект.Товары Цикл
        НомерСтроки = СтрокаТоваров.НомерСтроки;
        Товар = Строка(СтрокаТоваров.Номенклатура.УникальныйИдентификатор());
        Данные = Новый Структура("ref, lineNo, item, qty",
            ИдентификаторКомплекта, НомерСтроки, Товар, СтрокаТоваров.Количество);

        КлючСтроки = СтрШаблон("%1:%2", ИдентификаторКомплекта, НомерСтроки);
        Сообщения.Добавить(кфкИнтеграция.ПараметрыСообщения(Данные, КлючСтроки));
    КонецЦикла;

    кфкИнтеграция.ПоместитьВОчередьИсходящих(Сообщения, "catalog.rows", Свойства.Продюсер);
    Возврат Неопределено;

КонецФункции
```

Шапка получает статус **Обработка отменена**. Каждая строка получает собственную запись очереди. Конструктор включает ключ строки в готовое сообщение, а адаптер использует его для регистрации. Для постоянной идентификации строки при перестановках берите отдельный UUID строки из прикладных данных.

## Проверка { #verification }

Запишите комплект с двумя строками и проверьте появление двух сообщений в `catalog.rows`. У сообщений должен быть общий `ref` и разные `lineNo`. Параллельная выгрузка и разные ключи Kafka допускают разный порядок доставки строк.

Для движений регистра используйте тот же способ. В обработчике первого правила сначала [получите записи по регистратору](outgoing-recorder.md), затем зарегистрируйте готовое сообщение на каждую строку под отдельным ключом маршрутизации.
