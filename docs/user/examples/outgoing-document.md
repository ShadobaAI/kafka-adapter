# Сериализация документа с табличной частью

Пример формирует одно сообщение с реквизитами документа `ЗаказКлиента` и массивом строк табличной части `Товары`. Используются колонки `Номенклатура` и `Количество`. Замените имена на реквизиты своего документа.

## Настройка и код { #handler }

Укажите в продюсере `Документ.ЗаказКлиента`, топик `orders` и полное имя функции `ОбменKafkaСервер.СериализоватьЗаказ`. Выберите тип **Произвольный обработчик**.

```bsl
Функция СериализоватьЗаказ(Объект, Свойства, ТекстЖурнала, Отказ) Экспорт

    Идентификатор = Строка(Объект.Ссылка.УникальныйИдентификатор());
    Строки = Новый Массив;
    Для Каждого СтрокаТоваров Из Объект.Товары Цикл
        Товар = Строка(СтрокаТоваров.Номенклатура.УникальныйИдентификатор());
        Строки.Добавить(Новый Структура("item, qty", Товар, СтрокаТоваров.Количество));
    КонецЦикла;

    Данные = Новый Структура("ref, number, dateTime, deleted, lines",
        Идентификатор, Объект.Номер, Объект.Дата, Свойства.ЭтоУдаление, Строки);

    Возврат кфкИнтеграция.ПараметрыСообщения(Данные, Идентификатор);

КонецФункции
```

## Проверка { #verification }

Запишите заказ с двумя строками. Проверьте, что в топик пришло одно сообщение с двумя элементами `lines`. Для пустой табличной части массив будет пустым.

Предельный размер тела зависит от конфигурации Kafka и клиента. Если документ или массив строк превышает допустимый размер, используйте [отдельные сообщения для строк](outgoing-split-rows.md) или согласуйте другой контракт.
