# Создание или обновление элемента справочника

Обработчик создаёт элемент `Номенклатура` по UUID из поля `ref` или обновляет элемент с тем же UUID. Вход содержит также `code` и `name`.

```json
{
  "ref": "fce2f368-d7db-4bbb-8f5f-904492df0f40",
  "code": "N-100",
  "name": "Тестовый товар"
}
```

## Настройка консьюмера { #consumer-setup }

Выключите **Двоичные данные**. Для нужного топика выберите **Произвольный обработчик** и укажите `ОбменKafkaСервер.ЗагрузитьНоменклатуру`. Поместите процедуру в одноимённый серверный общий модуль. Добавьте заполнение обязательных реквизитов вашей конфигурации.

## Код обработчика { #handler }

```bsl
Процедура ЗагрузитьНоменклатуру(ТелоСообщения, Свойства, ТекстЖурнала, Отказ) Экспорт

    Данные = ОбщегоНазначения.JSONВЗначение(ТелоСообщения, "", Ложь);
    Ссылка = Справочники.Номенклатура.ПолучитьСсылку(
        Новый УникальныйИдентификатор(Данные.ref));
    Элемент = Ссылка.ПолучитьОбъект();

    Если Элемент = Неопределено Тогда
        Элемент = Справочники.Номенклатура.СоздатьЭлемент();
        Элемент.УстановитьСсылкуНового(Ссылка);
    КонецЕсли;

    Элемент.Код = Данные.code;
    Элемент.Наименование = Данные.name;

    кфкИнтеграция.Отключить(Элемент);
    Элемент.Записать();

КонецПроцедуры
```

`Отключить` подавляет регистрацию записи в исходящей очереди, если справочник участвует в обратном обмене. Для режима загрузки, который нужен прикладным обработчикам вашей конфигурации, можно дополнительно установить `Элемент.ОбменДанными.Загрузка = Истина`. [Контракт обработчика](../development/consumer-handler.md#writing-data)

## Проверка { #verification }

1. Отправьте JSON и убедитесь, что запись получила статус **Обработано**, а в справочнике появился элемент с указанным UUID.
2. Отправьте сообщение с тем же `ref` и изменённым `name`. У существующего элемента должно измениться наименование.
