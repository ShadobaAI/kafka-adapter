# Идемпотентность по содержимому

Адаптер сравнивает хэш тела с последней успешной операцией по тому же `КлючЗаписи`. Это позволяет пропустить повтор с неизменным телом, пока хэш хранится в регистре.

| Направление | Флаг | Статус при совпадении |
|---|---|---|
| Из 1С в Kafka | [Идемпотентная отправка](../configuration/producers.md#idempotent-send) | **Выгрузка отменена**. «Сообщение уже выгружено». |
| Из Kafka в 1С | [Идемпотентная обработка](../configuration/consumers.md#idempotent-processing) | **Обработка отменена**. «Сообщение уже обработано». |

Для исходящих ключ записи учитывает продюсер, тип регистрации и ключ исходных данных. Для входящих — консьюмер, топик и ключ из Kafka. Совпадение хэша сравнивается только внутри соответствующего ключа записи. Если меняете Kafka-ключ или тело при каждом вызове, повтор может не совпасть с предыдущими данными.

## Проверка { #verification }

1. Включите соответствующий флаг и [примените настройки](../configuration/jobs.md#settings-restart).
2. Отправьте сообщение с постоянными ключом и телом. Дождитесь статуса **Выгружено** или **Обработано**.
3. Зарегистрируйте его повторно или опубликуйте в Kafka второе входящее сообщение с теми же ключом и телом. Проверьте статус отмены и текст журнала.
4. Измените тело при том же ключе. После успешной операции адаптер сохранит новый хэш.

Чтобы осознанно повторить обмен без проверки хэша, можно временно снять флаг и зарегистрировать новую запись. Для продуктивного обмена учитывайте, что настройка применяется ко всему продюсеру или консьюмеру.

Дедупликация регистраций и `enable.idempotence` клиента работают на других этапах. [Дедупликация продюсера](../configuration/producers.md#registration-deduplication) · [Идемпотентный клиент Kafka](../configuration/producers.md#enable-idempotence)
