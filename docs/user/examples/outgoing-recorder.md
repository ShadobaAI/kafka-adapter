# Выгрузка движений по регистратору

Адаптер регистрирует изменение набора записей по регистратору. В произвольный обработчик приходит структура с полем `Регистратор`. Пример запрашивает движения этого документа одним запросом и публикует их массивом в одном сообщении.

## Настройка и код { #handler }

В **Тип объект** продюсера укажите `РегистрНакопления.ТоварыНаСкладах`, выберите топик `stock.movements` и экспортную функцию **Произвольного обработчика**. Укажите имя регистра и полей из своей конфигурации.

```bsl
Функция СериализоватьДвижения(Объект, Свойства, ТекстЖурнала, Отказ) Экспорт

    Запрос = Новый Запрос(
        "ВЫБРАТЬ
        |    Движения.Номенклатура КАК Номенклатура,
        |    Движения.Количество КАК Количество
        |ИЗ
        |    РегистрНакопления.ТоварыНаСкладах КАК Движения
        |ГДЕ
        |    Движения.Регистратор = &Регистратор");
    Запрос.УстановитьПараметр("Регистратор", Объект.Регистратор);
    Выборка = Запрос.Выполнить().Выбрать();

    Строки = Новый Массив;
    Пока Выборка.Следующий() Цикл
        Товар = Строка(Выборка.Номенклатура.УникальныйИдентификатор());
        Строки.Добавить(Новый Структура("item, qty", Товар, Выборка.Количество));
    КонецЦикла;

    Идентификатор = Строка(Объект.Регистратор.УникальныйИдентификатор());
    Данные = Новый Структура("recorder, lines", Идентификатор, Строки);
    Возврат кфкИнтеграция.ПараметрыСообщения(Данные, Идентификатор);

КонецФункции
```

## Проверка { #verification }

Запишите движения документа в регистр. После выгрузки проверьте, что сообщение содержит UUID регистратора и его текущие движения. Отдельно проверьте семантику пустого массива, если получатель применяет сообщение как новый снимок движений.

При использовании КД 3.1 адаптер запрашивает строки по регистратору и применяет правила к каждой записи. [Режим КД 3.1](../development/conversion-data.md) · [Одно сообщение на строку](outgoing-split-rows.md)
