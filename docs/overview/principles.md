# Принципы и ограничения

Состояние очередей хранится в базе 1С. При восстановлении обмена проверяйте состояние записи и журнал её обработки. Как посмотреть результат по этапам, показано на странице [Потоки данных](data-flow.md#where-to-check).

## Повторы и дубли { #retries-and-duplicates }

| Ситуация | Поведение адаптера |
|---|---|
| Несколько исходящих регистраций одного ключа | По умолчанию к сериализации и отправке отбирается последняя подходящая регистрация. Флаг **Отключить дедупликацию** допускает обработку более ранних регистраций. [Дедупликация регистраций](../user/configuration/producers.md#registration-deduplication) |
| Совпало тело сообщения | При включённой идемпотентности адаптер сравнивает хэши по ключу записи отдельно для выгрузки и обработки. [Контроль повторов по хэшу](../user/examples/idempotency.md) |
| Ошибка отправки в Kafka | Адаптер может повторить отправку в пределах счётчика попыток. [Автоматический повтор](../user/operations/statuses.md#automatic-retry) |
| Входящий обработчик попросил подождать | Адаптер оставляет сообщение новым и повторяет обработку после задержки, если запрос укладывается в лимиты. [Отложенный повтор](../user/development/consumer-handler.md#deferred-retry) |

Сквозной гарантии exactly-once для обработки в 1С нет. Для прикладных записей используйте устойчивый ключ и учитывайте повторный вызов обработчика. Исходящая регистрация ссылки хранит ссылку на объект: сериализация читает его актуальное состояние. Если получателю нужно отдельное событие на каждое изменение, формируйте тело и ключ каждого события при регистрации. [Произвольные события](../user/examples/custom-events.md)

## Порядок и размер сообщений { #order-and-size }

Фоновые потоки обрабатывают сообщения параллельно. Очередность отбора в 1С сама по себе не задаёт порядок завершения обработки. Если порядок событий важен для прикладной операции, учитывайте ключ и версию события в контракте обмена.

Допустимый размер сообщения зависит от настроек брокера, топика и клиента Kafka. При поиске причины ошибки проверяйте весь маршрут от продюсера до консьюмера. Способ отправить части данных отдельными сообщениями показан в [примере разделения строк](../user/examples/outgoing-split-rows.md).

Требования к режиму информационной базы и версиям компонентов приведены в [инструкции по установке](../user/installation/requirements.md). Настройки индексов и рекомендации по нагрузке находятся в разделе [Производительность](../user/operations/performance.md).
