# Частые вопросы

Короткие ответы и ссылки на подробные инструкции. Для настройки первого обмена выберите маршрут [из 1С в Kafka](../start/outgoing.md) или [из Kafka в 1С](../start/incoming.md).

В FAQ можно быстро найти ответ на вопрос. Пошаговые проверки по симптомам и действия после устранения ошибки собраны в [Типовых проблемах](../user/operations/troubleshooting.md).

## Установка и подключение { #installation }

### Какие платформа и БСП нужны?

Платформа запуска — **8.3.26+**, БСП — **3.1.10+**, режим информационной базы — клиент-серверный. Файловый режим не поддерживается.

Подробнее: [требования к платформе, БСП, лицензии и ОС](../user/installation/requirements.md).

### Подключать расширением или в основную конфигурацию?

Расширение рекомендовано для типовых и регулярно обновляемых конфигураций; встраивание — для глубоко кастомизированных решений.

Подробнее: [сравнение способов подключения](../user/installation/index.md#сравнение-вариантов).

### Нужно отдельно устанавливать внешнюю компоненту?

Компонента Simple Kafka Connector 1C встроена в подсистему; отдельная установка и регистрация не требуются.

Подробнее: [требования к окружению и компоненте](../user/installation/requirements.md).

### Какие права назначить пользователям?

Назначайте роли адаптера по задачам пользователя. Для пользователя обмена дополнительно нужны права и доступы для фоновых заданий.

Подробнее: [кому какие роли назначить](../user/installation/roles.md#кому-что-назначить), [требования к пользователю обмена](../user/configuration/jobs.md#требования-к-пользователю-обмена).

## Настройка обмена { #configuration }

### Что выбрать: продюсер или консьюмер?

Продюсер отправляет данные **из 1С в Kafka**, консьюмер получает их **из Kafka в 1С**. Для двустороннего обмена нужны обе настройки.

Подробнее: [настройка продюсера](../user/configuration/producers.md), [настройка консьюмера](../user/configuration/consumers.md), [маршруты первого обмена](../start/index.md).

### Где указать SASL и SSL/TLS?

Параметры подключения задаются в брокере; для секретных значений включайте **Режим пароля**.

Подробнее: [защищённое подключение в настройках брокера](../user/configuration/brokers.md#защищённое-подключение), [примеры SASL и SSL/TLS](../user/examples/secure-connection.md).

### Возникает ошибка «Broker: Topic authorization failed». Что делать? { #topic-authorization }

Проверьте существование топика, права учётной записи Kafka и точность имени топика. Частые причины: топик не создан и нет прав на его создание; топик существует, но нет прав на работу с ним; в имени перепутаны регистр или похожие латинские и кириллические символы.

Подробнее: [порядок проверки доступа к топику](../user/operations/troubleshooting.md#topic-authorization), [параметры подключения к брокеру](../user/configuration/brokers.md#параметры-подключения).

### Каталог логирования нужен на сервере 1С или на клиентской машине? { #log-directory }

Для файловых логов компоненты Kafka укажите каталог, доступный **на сервере 1С**. Путь только на клиентской машине не подходит: файлы создают серверные процессы 1С, которым нужен доступ на запись в этот каталог.

Подробнее: [каталог и файлы логирования компоненты](../user/configuration/logging.md#логирование-компоненты-kafka).

### Изменил настройки, но обмен работает по-прежнему. Что делать? { #settings-not-applied }

Нажмите **Перезапустить** в **Kafka / Администрирование / Фоновые задания**. Настройки кэшируются при старте потока, поэтому уже работающий поток продолжает использовать прежние значения.

Подробнее: [как применить изменения настроек и перезапустить потоки](../user/configuration/jobs.md#settings-restart).

### Почему два консьюмера получают разные сообщения?

Консьюмеры с одинаковым `consumer group id` делят партиции и сообщения между собой. Для независимых потоков используйте разные группы.

Подробнее: [идентификатор группы и основные поля консьюмера](../user/configuration/consumers.md#основные-поля).

### Когда включать потоковый режим?

При высокой нагрузке, когда запуск фонового задания занимает существенное время по сравнению с обработкой порции. Для редкого обмена оставьте обычный режим.

Подробнее: [потоковый режим](../user/configuration/jobs.md#потоковый-режим).

## Разработка интеграции { #integration }

### Какие модули можно вызывать из прикладного кода?

Публичный API расположен в `кфкИнтеграция` на сервере и `кфкИнтеграцияКлиент` на клиенте. Сигнатуры внутренних служебных модулей могут меняться.

Подробнее: [публичные методы и их параметры](../user/development/api.md), [разработка интеграции](../user/development/index.md).

### Как отправлять события без привязки к объекту 1С?

Задайте произвольный ключ регистрации в продюсере и передавайте его при регистрации через API.

Подробнее: [регистрация сообщений через API](../user/development/api.md#поместитьвочередьисходящихисточник-типобъект-продюсеры), [полный пример произвольных событий](../user/examples/custom-events.md).

### Как избежать обмена по кругу при загрузке данных?

В обработчике консьюмера подавляйте повторную регистрацию перед записью объекта.

Подробнее: [причина и решение кругового обмена](../user/operations/troubleshooting.md#сообщения-уходят-в-очередь-по-кругу), [полный пример входящего справочника](../user/examples/incoming-catalog.md).

### Как управлять повторной отправкой и обработкой?

Настройки идемпотентности продюсера и консьюмера сравнивают содержимое сообщений с историей по ключу записи очереди. Учитывайте срок хранения этой истории и различия направлений.

Подробнее: [идемпотентная отправка](../user/configuration/producers.md#идемпотентная-отправка), [идемпотентная обработка](../user/configuration/consumers.md#идемпотентная-обработка), [сценарии повторной отправки и обработки](../user/examples/idempotency.md).

### Можно работать синхронно, без очередей?

Да, для таких сценариев предусмотрен прямой API.

Подробнее: [справочник прямого API](../user/development/direct-api.md), [примеры отправки и чтения](../user/examples/direct-api.md).

### Где описаны AsyncAPI, XDTO и конвертация данных?

Описание контракта, модель данных и правила конвертации собраны в отдельных разделах.

Подробнее: [контракт AsyncAPI и XDTO](../project/index.md#контракт-данных-asyncapi-и-xdto), [КД 3.1](../user/development/conversion-data.md), [генерация XSD](../project/xsd-generation.md).

## Эксплуатация и ошибки { #operations }

### Сообщения остались в статусе «Новое». Что проверить?

Начните с проверки запуска обработки и блокировок. Пошаговый порядок диагностики приведён в эксплуатационном разделе.

Подробнее: [сообщения застряли в статусе «Новое»](../user/operations/troubleshooting.md#сообщения-застряли-в-статусе-новое), [мониторинг очередей](../user/operations/monitoring.md).

### Ошибки выгрузки и обработки повторяются автоматически?

При **ошибке выгрузки** предусмотрены автоматические повторные попытки; при **ошибке обработки** требуется ручное вмешательство.

Подробнее: [правила автоматического повтора](../user/operations/statuses.md#автоматический-повтор), [диагностика ошибки выгрузки](../user/operations/troubleshooting.md#статус-ошибка-выгрузки), [диагностика ошибки обработки](../user/operations/troubleshooting.md#статус-ошибка-обработки).

### Как приостановить обмен и обслужить очередь?

Сначала остановите потоки через блокировку обмена. Очистка очереди требует нужных прав и остановленного обмена.

Подробнее: [управление фоновыми заданиями](../user/configuration/jobs.md#фоновые-задания), [ручная очистка локальной очереди](../user/operations/queue-maintenance.md#ручная-очистка-локальной-очереди).

### Где смотреть ошибки и настраивать уведомления?

Ошибки доступны в очередях, истории обмена и диагностических журналах; уведомления настраиваются отдельно.

Подробнее: [мониторинг](../user/operations/monitoring.md), [диагностика](../user/operations/diagnostics.md), [логирование](../user/configuration/logging.md), [алерты и контроль](../user/configuration/alerts.md).
